# SorcerStone — лабораторна робота: оптимізація пам'яті

## Пропозиції щодо оптимізації пам'яті

1. **Завантаження всього файлу в пам'ять.** Раніше `Files.readString()` створював рядок із цілим текстом. Я замінила це на поступове читання через `BufferedReader`.
2. **Великі тимчасові об'єкти.** Попередня версія тримала весь текст під час аналізу. Тепер для читання використовується буфер фіксованого розміру.
3. **Копія тексту під час `toLowerCase()`.** Я прибрала перетворення всього тексту в нижній регістр.
4. **Перетворення регістру окремих символів.** Великі англійські літери переводяться в нижній регістр під час читання.
5. **Регулярний вираз для всього тексту.** Замість `Matcher` над повним рядком я використала посимвольний аналіз.
6. **Залежність обсягу вхідних даних від пам'яті.** Розмір буфера становить 8192 символів незалежно від розміру файлу.
7. **Зберігання всіх слів.** Я не створюю масив усіх токенів, а відразу підраховую частоти.
8. **Зайві проміжні колекції.** Для підрахунку використовується одна мапа частот.
9. **Повторне використання буфера слова.** Один `StringBuilder` використовується для всіх слів.
10. **Створення слова тільки після його завершення.** Рядок створюється лише коли зустрічається роздільник або кінець файлу.
11. **Слова на межі буферів.** Я додала обробку випадку, коли одне слово починається в одному буфері, а закінчується в іншому.
12. **Останнє слово без роздільника.** Додала його обробку після завершення читання.
13. **Закриття файлового потоку.** Використала `try-with-resources`, щоб файл закривався автоматично.
14. **Сортування всіх унікальних слів.** Раніше для топ-30 створювався список усіх записів мапи.
15. **Обмежена черга для топ-N.** Тепер використовується `PriorityQueue`, яка зберігає не більше N кандидатів.
16. **Менше посилань у пам'яті під час сортування.** Новий алгоритм сортує лише підсумковий список із максимум N елементів.
17. **Однакові частоти.** Зберегла алфавітне сортування для відтворюваних результатів.
18. **Порожні файли.** Програма повертає порожню мапу без зайвих операцій.
19. **Нульовий ліміт.** Метод `topWords()` відразу повертає порожній список.
20. **Перевірка результату оптимізації.** Додала тести, які порівнюють новий підрахунок із попередньою версією.
21. **Вимірювання часу.** Для порівняння використала `System.nanoTime()`.
22. **Вимірювання пам'яті.** Додала `Benchmark.java`, який показує пікове використання Java heap за даними JVM.
23. **Окремі запуски для кожної версії.** Рекомендую запускати їх в окремих JVM, щоб зменшити вплив попереднього тесту.
24. **Однакові вхідні дані.** Обидві версії потрібно тестувати на одному файлі.
25. **Повторюваність вимірювань.** Для висновків слід виконати декілька запусків і порівняти медіани, а не один результат.


- `PreviousMain.java` — попередня версія для порівняння.
- `Main.java` — оптимізована версія.
- `MainTest.java` — тести правильності результатів.
- `Benchmark.java` — вимірювання часу й пікового Java heap.
